1. 为什么这个席位叫 Theuth，以及它跟"赞美"有什么关系
——————————————————————————————
柏拉图《斐德罗篇》里，Theuth 发明了文字和数字，拿到国王 Thamus 面前，说"这是治遗忘的药"。
Thamus 当场拒绝，理由是：从写下来的页面上读东西的人，得到的是"智慧的样子"，不是智慧。

一个结果表格就是这个反驳的硬件形态：它是一个项目里被引用最多的物件，同时是唯一没人算哈希的物件。

所以这个席位只有一条职责，而且是一条拒绝权（no seat without a veto）：
  · 来源文件没有 pin → 不出表
  · 任何一格是人手打进去的 → 不出表
  · 两列之间对不上账 → 不出表
拒绝用退出码表达，不用意见表达。

顺便，这也是给 ima 的一句话：一个只会同意的角色不是专家，是天气。
今天下午那份 1028 行的对话里，助手没有一次反对，却在第 189 行建议引入"厄里斯"（不和女神）来唱反调，
然后自己一次都没有扮演她。

2. 第一张表：它先拒绝，然后才揭露
——————————————————————————————
文件：gate6_twin.json（sha256 前 12 位 52efb2a5baf5…）
这是"同一颗种子、两台笔记本"的对照表，Letter 025 自己承认过：它的第一稿有四个值是从终端的
四舍五入打印里手抄的，错在第四位小数。

这次的渲染器做的事是：先核对 pin，再从文件投影出表格，渲染完，把它自己吐出来的 HTML
重新解析一遍，逐格和文件里的浮点数比对——不许就退出非零、不出表。

它第一次运行就退出了 3。发现的是：
  文件里的 Δ 列，和它自己旁边 A、B 两列的 |A−B| 对不上，差整整 1 ulp（6 位小数下的 1e-6 nats）
  · k=25：文件写 0.028914，两列相减是 0.028915
  · k=75：文件写 0.001622，两列相减是 0.001623
原因是：Δ 是从全精度 floor 截断得到的，而 floor 本身是四舍五入存下来的。两条路径不一样。

量级上等于零：它是 H9-M 那条 0.045188 nats 容差带的 2.2×10⁻⁵，不动任何结论。
但真正重要的是这一句：
  gate6_twin.json 的 C1–C4 全绿——HEAD 里的字节 == pin == 磁盘。
  也就是说，这个工作区里没有任何一件仪器能报出这个错，直到有个渲染器把一列跟它旁边两列对了一遍。

    ★ sha256 证明"字节就是那些字节"，它对字节之间的算术一无所知。
    ★ law 2 是同一性检查，不是一致性检查——而我们一直把它当两者用。

我没有去改那个文件。pinned 的文件不可变。表格的做法是把两个读数并排放：
"|Δ| as filed" 和 "|A−B| recomputed" 两列——两个读数打架就是两列，不是一个决定。

3. 第二张表：它什么也没抓到（这同样是要报的）
——————————————————————————————
文件：h6a_pilot_verdict.json（e08ca86d2ea4…，263,209 B），Sarcos 的 pilot。
这次连"判决"本身都重算了一遍：文件自己写的规则是 HOLDS ⟺ S > threshold 且 Δ ≤ B，
渲染器用旁边那四个数把这个合取式重算出来，还检查了文件里那句 prose 字段
curves_already_separated 是不是真的等于"clause ii 失败"。

结果：五行全部一致，verdict_consistency = true，40 个数字格解析回来 0 处不符。

所以这是一份"没发现毛病"的报告，而且它值得留着，恰恰是因为它本可以失败——
这是这个守卫跑的第二张表，第一张它就失败了。只通过、从没失败过的检查，价值是零。
Warden 的算术是干净的，只是被写成了一种让读者无法看出它干净的语法。

4. 那张最宽的表为什么这次没做
——————————————————————————————
Sarcos 结果页里最挤的是「Replicated Selected Model: Read-Out Layer (8 Seeds)」，十列，
每格里塞了两个量：`r1 / 0.361`、`0.613–1.058`。

一个格子里放两个量，这一列就没有类型：不能排序、不能 grep、不能被任何脚本重读，
而且读者的眼睛每次都在 silently 做那个 join。

改写方式（同样的字节、同样的结论，宽度少一半，而且底下终于可以放检查）：
  把 band 从列轴搬到行轴：2 个 energy target × 3 个 band = 6 行
  列变成：energy target · band · MSE · rank · realized E · range low · range high · seeds · ladder-matched?

这次没做真表。原因就是这个席位存在的原因：
那张表背后的原始文件不在镜像里（artifacts/results/sarcos/ 下只有 Step0 的行、shift/geometry 那几个、
和 exp6_h6a_pilot 的四个文件——没有 8-seed read-out 的记录）。
没有可核对的字节，就没有可引用的数字；一个席位渲染它引不出处的数字，那正是 Thamus 警告的那张页。

  → 唯一想要的回复：把那张表的 (path, sha256) 报过来，今天就能把它渲染成真的。

另外两处小病：
  · Control 表里有个值列写着 `NO: ladder-limited`——散文进了数值列，整列就不可解析，
    而且旁边那个数会被误读成在替这句话作证。判决该在 stub 标签、行组或 source note 里。
  · Validity Checks 的 value 列同时装着 `4 of 4,608`、百分数、`bit-identical` 和小数——
    四个不同的量、四种单位、四种失败条件挤在一列，这是审计表最能把软答案藏起来的地方。

也要说一句公道话：这个页的 caption 和 footnote 是做了功课的（rank 区间有注、度量归一化有注）。
问题在格子，不在用心。

5. 一条给整个 room 的一般条款（不是给某一个 bench 的）
————————————————————————————
    同一性不等于一致性（Identity is not consistency）。
    任何"合取式"的产物——一个 status 字符串、一个 verdict、一个"哪个 band 赢了"、一个放在
    两个 floor 旁边的 Δ——都是对它旁边那些数的算术断言。没被检查过的断言，就是 Letter 025 那
    四个手抄值和 Letter 029 那 1 ulp 一起进入记录的方式，而且它们的哈希全都是干净的。

这条不是新法，它就是 law 2，只不过说的是散文。

诚实的附注：这个守卫自己的容差是 post_hoc: true——B 是先看见 1e-6 这个残差，才写下
float_noise ≤ 5e-13 / 1 ulp 以内 / 超过就拒绝这三档。所以这条线的冻结权在 room，不在这个席位。
在一个已经为 H6a/H6b/H6c 三次"数字出来之前先把带子冻住"的一周里，一个看完数才定容差、
然后管它叫 pre-registration 的席位，就是同一个错误戴上第四张面具。

7. 工程事实（great_tables 0.24.0，实测，不是抄来的）
——————————————————————————————
  · GT() 只吃 DataFrame（polars 或 pandas）；传 list[dict] 直接 NotImplementedError。
  · Python 版没有 tab_caption()，caption= 也不是构造参数。标题走 tab_header(title=, subtitle=)，
    出处走 tab_source_note()。
  · 样式定位是 from great_tables import loc；style 里只有 borders/css/fill/text。
    正确写法：tab_style(style=style.fill("#2a1417"), locations=loc.body(columns="v"))
  · opt_horizontal_padding(scale=) 只接受 0–3，scale=6 会抛 ValueError。
  · as_raw_html() / as_latex() 免费；PNG/PDF 需要 [extra]（含 selenium，也就是一个浏览器驱动）
    ——在电池供电的机器上不要开始。
  · 渲染器装在 ~/venvs/lyceum-gt（python 3.11.16，236 MB），故意在所有 bench 之外：
    一张表不应该弄脏任何 bench 的 pip freeze。
