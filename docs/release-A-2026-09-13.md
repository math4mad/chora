## 3 · Four things this run caught itself doing — all of them mine, all of them the same genus

1. **A published restore recipe that does not work.** The release body told the reader to
   `git checkout -B here 20260913A` — a tag that has never existed, because the script built the tag
   name out of the *directory* name with the dashes stripped, two lines away from `heads.txt` where the
   true tag was already written. Found by reading the published page; the body is corrected in place
   with the mistake named on it. **This is B's `git clone <bundle>` lesson, relearned one layer up**:
   a wrong recipe is worse than none, because it gets trusted during an emergency.
2. **A retry loop that never ran.** `bin/verify-release.sh` wrote its temp lists without a trailing
   newline; `while read` drops the last unterminated line; the one missing asset was the *only* line,
   so the "retrying missing assets" loop printed its header and did nothing. A tool whose repair path
   silently no-ops reports success while still broken.
3. **A name GitHub rewrites.** `git bundle create "…/Polynomial-Activated NN.bundle"` — the space
   survives locally, but the release API returns `Polynomial-Activated.NN.bundle`. The first upload
   attempt failed outright (a name with a space in a query string), and the verifier called the result
   MISSING until it was taught to accept either spelling and prove the file by **hash**. `backup-drill.sh`
   now sanitises names at the mint so the local file and the remote asset agree.
4. **Twice in two minutes, my own quoting executed git.** Markdown backticks inside a double-quoted
   bash string were command-substituted — the second one ran
   `git checkout -B here 20260913A` *in the working repository*. It failed harmlessly (no such commit,
   no branch created — verified: `branch --list here` → 0, HEAD unchanged, reflog shows only the beat's
   own snapshots), but the near-miss is the point: **unquoted markdown text is not a safe argument to a
   shell that can write to this repo**, and this workspace has just learned twice that the instrument
   and the object are the same bytes. Text from a page goes into files, and files get quoted.

## 4 · Cadence, offered as practice (Meeting 004 has it as part of Q3/Q4)

* Mint with `backup-drill.sh` **before** a registered run series begins, and print the delta since the
  last tag — so the parachute is always younger than the work it protects.
* Publish with `publish-release.sh`, verify with `verify-release.sh`. **The verify step is the
  backup**; the mint is only the intent.
* Any day the six repos are clean, a re-mint costs ~40 s and 219 MB of bandwidth.
